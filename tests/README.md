# 文枢隔离验证

## 1. 默认入口：不接触真实服务或文档库

从仓库根目录运行，要求 Python 3.12 及 Git：

```bash
python -B custom/tests/static_check.py
python -B tests/baseline/run.py
```

也可在应用目录运行 `npm test`。入口使用固定模块白名单，不扫描旧集成测试。Python 标准库执行 HTTP、缺陷门禁和构建驱动的单元契约，服务的 Git/build 写入结果及构建单元契约的 npm 结果均为合成数据。另有两个夹具契约在新临时副本运行真实 Python 同步/生成脚本，不安装 npm、不调用 Node，也不接触真实库；针对性负例要求坏链接或坏搜索记录仍产生普通失败。另用只读 `git check-ignore` 确认两份合成附件示例（含下载白名单外的负例）可进入干净 CI checkout、未列入 Git 豁免的其它附件仍被忽略；不执行真实 Git 写入。这些单元契约不能替代下一节的真实构建。

[测试器](<baseline/run.py>) 执行前验证每个登记缺陷恰有一个用例。未知、缺失、重复标签、零测试、空模块、导入错误、跳过检查、普通断言和基础设施异常都阻断结果。

## 3. 临时目录、凭据与证据

[HTTP 沙箱](<baseline/sandbox.py>) 将服务源码复制到新临时应用，先写入测试配置、会话/分享与文档/站点夹具，再导入副本。只监听回环地址随机端口；Git 和构建调用被严格合成边界拦截，未预期命令或未消费的故障脚本都会失败。

[临时目录助手](<baseline/tempdirs.py>) 在 Windows 继承当前测试进程已有权限，POSIX 使用仅所有者权限；不修复或扩大 ACL，不隐藏清理错误。必要时设置进程级 `WENSHU_TEST_TMPDIR` 到已存在且确认为自有的临时父目录；仓库内仅允许显式配置到被忽略的 `tests/.baseline-tmp/`。普通源码目录、非临时目标、父目录穿越及链接/reparse point 会在创建临时树前被拒绝；不要把变量指向真实库或应用。

两个 CLI 都接受 `--report <临时目录中的新文件>`：父目录须已存在，临时位置校验在运行前及发布时执行，使用独占创建，不覆盖既有文件、不创建任意父目录、不写入源应用。基线报告为 UTF-8 JSON，包含状态、运行数、失败/错误/跳过、预期失败、覆盖和每个缺陷的观察记录。基线 CLI 标准输出仅给出 JSON，测试诊断保留在标准错误；构建 CLI 保留真实工具输出并给出结构化结果。

[CI](<../.github/workflows/ci.yml>) 在 Windows / Linux 分别运行静态检查、显式基线和真实隔离构建，保存已生成的 JSON；前置步骤阻断时后续构建不运行，不保证两份报告都存在。该工作流已于 2026-11-17 在 GitHub Actions 实际执行通过（run 44044221090，ubuntu-latest 与 windows-latest 两个 job 均为 success，含真实 Astro/Pagefind 构建）；临时根通过 step 级 `WENSHU_TEST_TMPDIR` 指向 `runner.temp`，`runner` 上下文写进 job 级 env 会让整份工作流被判非法。新增或修改工作流后仍以对应运行记录与 artifact 为准。

## 4. 八项普通安全回归、九项读取与请求加固、主题治理与当前零项登记

2026-11-17，本轮仅修复 WS-001/WS-002 的 GET 编码路径穿越：[服务实现](<../custom/server.py#L2268-L2273>) 在静态授权前复用实际文件读取的路径转换，统一解码、点段归一化与平台路径段过滤；不改写原请求，也不增加二次解码或扩大公开资源白名单。

同日，WS-004 也已修复：[服务实现](<../custom/server.py#L151-L160>) 新增 `doc_path_segment()`，在 `project`、`domain`、`filename` 三处入口先拒绝绝对路径、盘符/UNC 前缀与上级目录或点路径段，再由 :1764-1767 的 `relative_to(DOCS)` 兜底。越界写入被拦在创建之前，合法的相对嵌套路径不受影响。

同日，WS-003 也已修复：[服务实现](<../custom/server.py#L1246-L1253>) 新增 `revoke_session()`，注销时先在既有锁内把当前 `ws_sid` 从会话存储移除并保存，再清 Cookie 并跳转 `/login`。已复制出去的旧会话 ID 立即失效，其它并行会话不受影响；会话有效期、Cookie 属性与登录流程均未改动。

同日，WS-005 也已修复：[服务实现](<../custom/server.py#L1940-L1956>) 把批量元数据更新改成两段式——先对全部目标校验存在性、淘汰状态、类型/状态兼容与 `changes` 适用性，全部通过后才逐个落盘。后项无效时前项保持字节不变，合法批量仍按原顺序全部更新。

同日，WS-006 也已修复：[服务实现](<../custom/server.py#L1673-L1681>) 不再丢弃 `git add -A` 的返回值：非零时使缓存失效、记一行失败日志并返回 500 与「Git add 失败：改动已写入文档库并完成构建，但未提交」，响应体不含 `ok`/`built`/`commit`。改动本身仍已落盘且可回读，只是不再被谎报为已提交；提交成功路径与构建回滚路径均未改动。

同日，WS-007 也已修复：[服务实现](<../custom/server.py#L1682-L1690>) 不再只把 `git commit` 的失败折成空提交号：非零时使缓存失效、记一行失败日志并返回 500 与「Git commit 失败：改动已写入文档库并完成构建，但未提交」，响应体不含 `ok`/`built`/`commit`。`git add` 失败与构建回滚两条路径未改动，成功路径仍返回 `rev-parse` 得到的真实短提交号。

同日，WS-008 也已修复：[服务实现](<../custom/server.py#L1653-L1687>) 在写入前记录 `DOCS` 内的文件与目录集合，构建失败时在 `git checkout -- .` 之后删除本次新建的未跟踪文件、再按深度倒序删除本次新建的空目录。回滚不再遗留构建失败的新文档，构建前已存在的文件与目录一律不动；构建失败的上报文案与救援补丁路径未改动。

同日，静态读取另补两项加固：LINK-001 与 AUTH-002。[服务实现](<../custom/server.py#L2343-L2405>) 抽出 `static_gate()` 与 `static_scope()`：前者把公开前缀、登录态、分享授权三者的判定收成一条共用门禁，后者在词法归一化之外再取 `os.path.realpath()` 比对站点根的 `resolve()`，真实路径越界即 404；目录联接/符号链接即便落在 `/fonts/` 这类公开前缀内也不再被服务。新增 `do_HEAD()` 复用同一道门禁，HEAD 不再绕过授权直读私有文件，分享页与拒绝页改为按 `head=True` 只发头不写正文。修复前，指向站点外的联接经 `/fonts/leak/secret.txt` 返回 200 外部 canary、经 `/fonts/docsleak/` 返回 200 私有文档正文与目录清单，未授权的 `HEAD /private.txt` 返回 200；修复后三处联接请求全部 404，`HEAD` 与 `GET` 状态码一致。

同日，REDIR-001 也已修复：[服务实现](<../custom/server.py#L145-L152>) 的 `safe_next()` 不再只拦 `//` 开头：值里出现反斜杠、制表符/换行或其它控制字符时一律回落到站点根。浏览器会把这些字符归一化成路径分隔符，`/\evil.example` 因此会解析成 `https://evil.example/`，登录后的跳转就变成开放重定向。同批修好 [redirect](<../custom/server.py#L1331-L1341>) 的非 ASCII 目标：`Location` 只能是 latin-1，中文文档路径先按 URL 规则转义再发头，否则编码头部时抛异常直接断连，浏览器拿不到任何响应。合法的站内路径（含中文）仍跳到原目标。

同日，BODY-001 也已修复：[服务实现](<../custom/server.py#L1578-L1594>) 新增 `request_body()`：请求体长度必须是非负整数且不超过 16 MiB，`do_POST` 与 `read_json_body()` 都改走它。此前直接 `int(Content-Length)` 再 `rfile.read()`，非数字会抛未捕获异常并断开连接（客户端只看到 `RemoteDisconnected`），负数或超大值则让 `read()` 一直等数据、把工作线程占死到超时。现在畸形长度回 400「Content-Length 非法」，负数或超限回 413「请求体过大或长度非法」，并在应答前标记连接不可复用，避免残留请求体错位到下一个请求。

同日，HEAD-001 也已修复：[服务实现](<../custom/server.py#L2329-L2376>) 把 `do_GET` 的动态路由表抽成共用的 `route_dynamic(path, qs)`，[do_HEAD](<../custom/server.py#L2432-L2441>) 改为先走同一张表、再走同一道 `static_gate()`，`json_response()` 与 `login_page()` 也按 `self.command` 跳过正文。此前 `do_HEAD` 只做静态门禁：未登录的 HEAD 一律被兜底重定向到 `/login?next=...`（`HEAD /login` 因此 303 到 `/login?next=/login`，逐跳自增嵌套永不落地），已登录的 HEAD 则因找不到同名文件变成 404；`/api/shares`、`/api/status-options`、`/api/share/ctx`、`/api/admin/*`、`/s/<token>` 的状态码全部与 GET 分叉。修复后这些路由的 HEAD 与 GET 状态码、`Location`、`Content-Length` 完全一致，正文仍为空。

同日，AUTH-003 也已修复：[服务实现](<../custom/server.py#L1577-L1591>) 的 `api_auth()` 改为先把请求头值与配置令牌都编码成 bytes，再做常量时间比较。`X-API-Key` 可以携带任意非 ASCII 字节，而 `secrets.compare_digest` 比较含非 ASCII 字符的 `str` 会抛 `TypeError`；此前该异常未被捕获，工作线程直接退出、连接零字节关闭，客户端连 401 都拿不到。现在任何输入都走同一条比较路径：非 ASCII 与错误 Key 一样得到 401「API Key 无效」，合法 Key、登录态与各管理接口的授权范围均未改动。

同日，BODY-002 也已修复：[服务实现](<../custom/server.py#L166-L178>) 新增 `doc_version()`，`/api/admin/create` 与 `/api/admin/version` 的显式版本号在写入前先按正整数校验：非数字、浮点、负数、零与 `null` 之外的容器类型一律 400「version 必须是正整数」。此前 `int(payload["version"])` 的 `ValueError` 落到通用异常分支，回 500「内部错误: invalid literal for int() ...」，既把内部异常文本回显给调用方，又可能在创建路径上先落盘再报错。现在非法值既不建文件也不改已有文档，合法的正整数版本仍照常写入。

同日，LOGIN-001 也已修复：[服务实现](<../custom/server.py#L151-L183>) 为登录加上按来源地址聚合的失败限速：[常量](<../custom/server.py#L33-L36>) 是 60 秒窗口内 5 次失败，[login_page](<../custom/server.py#L1413>) 可回 429 与 `Retry-After`。窗口内失败次数用尽后，连正确密码也先拒绝——否则爆破只要打到成功为止，限速就形同虚设；成功登录会清零该来源的计数，避免正常用户被自己的历史拖住。此前登录失败分支既不计数也不延迟，实测 30 次错密码全部 200、总耗时 0.12 秒，随后正确密码仍照常下发会话。限速只影响登录频率，密码比较方式、会话有效期与 Cookie 属性均未改动。
